## 一手證據

原 X 貼文已直接讀取。Matt 說與 Lauren Tan 交談後，更支持增加抽象並使用嚴格 lint；另提出省 token 與錯誤抽象較容易撤回的判斷。主貼文沒有提供 benchmark、實驗、媒體、repo 或外部連結。本文不引申為 Lauren 的逐字說法，也不將 token 與返工成本主張當成已證實結果。

- [ESLint no-restricted-imports](https://eslint.org/docs/latest/rules/no-restricted-imports)：paths、patterns、message；只針對 static imports，非動態 import／CommonJS require 的完整檢查。
- [ESLint flat config](https://eslint.org/docs/latest/use/configure/configuration-files)：files、linterOptions.noInlineConfig 與規則設定。示例只匹配 src/features/**/*.js，不冒充 TypeScript 設定或完整路徑解析器。
- [TypeScript narrowing](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#exhaustiveness-checking)：discriminated union 與 never 的分支完整性檢查，不等同業務正確性。
- [John Ousterhout 作者頁](https://web.stanford.edu/~ouster/cgi-bin/book.php)：第二版 A Philosophy of Software Design，通用模組與模組深度討論；未以此推導 AI token 成本。
