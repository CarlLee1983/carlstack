## 原文主張

作者主張 agent 不等於模型；它是模型加上任務、context、memory、tools、environment、permissions、verification、recovery 與 observability 的執行系統。文章將失敗拆為 task、context、model、tools、environment、verification、recovery 七層，並提出 H0–H3 maturity ladder、failure-attribution card 與可稽核的 `AgentEpisode`。

以下只能歸為作者的診斷框架，不能寫成已證明的普遍因果：

- 換更強模型仍在「相同邊界」失敗，**是** harness 問題的訊號，卻不是充分證明；模型和 harness 會交互影響。
- 七層、H0–H3、first divergence、episode package 都是有用的設計詞彙，不是業界標準或唯一分類。
- 文中的個人失敗案例沒有可重現任務、baseline、模型版本或量測方法，不能轉成成效宣稱。

## 一手資料核對

- **模型之外的系統邊界確實影響 agent 能做什麼（高確定性）。** OpenAI 描述 Codex 團隊早期進度受限於「underspecified」環境，並將改善重點放在工具、結構與可讀性；其個案不應外推為通用倍數成效。[OpenAI：Harness engineering](https://openai.com/index/harness-engineering/)
- **權限、隔離與 audit 必須是模型外的強制控制（高確定性）。** OpenAI 說明 sandbox 決定可寫入範圍與網路可達性，approval policy 決定跨界操作何時需核准，並保留 agent-native telemetry。[OpenAI：Running Codex safely](https://openai.com/index/running-codex-safely/)
- **短步數、人工介入與系統設計是現行 production agent 的常見選擇（中高確定性）。** IBM 的 20 個 case study／306 位實務者調查中，68% 的受訪 production agents 在人工介入前最多執行十步，74% 主要依賴人工評估；這是該樣本的描述，非最佳做法或所有工作負載的規則。[IBM Research：Characterizing Agents in Production](https://research.ibm.com/publications/characterizing-agents-in-production)
- **「固定模型、改 harness」可在特定 benchmark 得到提升（中確定性）。** AHE 預印本報告在 Terminal-Bench 2 上，十輪 harness 演化將 pass@1 從 69.7% 提至 77.0%，ablation 將收益定位於 tools、middleware 與 long-term memory；它是單一研究團隊的預印本與特定 benchmark，不能改寫為 production 保證。[Agentic Harness Engineering](https://arxiv.org/abs/2604.25850)
- **文章引用的 AI Harness Engineering 論文仍是預印本（中確定性）。** 該文提出 model–harness–environment、11 項責任、H0–H3 與 trace-based episode，但只報告 controlled validation task；可當概念來源，不可當已獨立驗證的 production 標準。[AI Harness Engineering](https://arxiv.org/abs/2605.13357)
- **可稽核的外部證據比 agent 自我宣告更可靠（高確定性）。** Git worktree 可提供同 repository 的多個工作樹與不同 branch checkout，適合隔離並行變更；但它不會消除 merge conflict、共用服務或憑證風險。[Git `worktree` manual](https://git-scm.com/docs/git-worktree)

## 建議文章角度：不要再重寫「七層 harness」

站內已發布〈[AI Agent 不可靠，先別急著換模型：Harness Engineering 的七個控制面](../../src/content/blog/harness-engineering-for-reliable-agents.mdx)〉，與本長文的中心論點高度重疊。優先考慮更新既有文或寫一篇窄文：**「Agent 失敗後，如何用 first divergence 做可否證的 failure attribution」**。

最小可落地做法：每次失敗只記錄預期結果、第一個偏離點、當時可得證據、責任層、缺少的控制、修復假說，以及一個能推翻該假說的重跑檢查。這能把「換模型」從預設反應改成可比較的實驗，但不能取代獨立驗證、人類核准或最小權限。
