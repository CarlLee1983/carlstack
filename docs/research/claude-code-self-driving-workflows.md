# Claude Code「環境讓代理自走」：來源查證筆記

> 研究日期：2026-08-31（Asia/Taipei）
> 分析對象：[swarm_japan 的 X 貼文](https://x.com/swarm_japan/status/2074607688257057121?s=12)。主 session 已透過瀏覽器讀取貼文可見全文；研究子程序的網頁擷取器未取得正文，因此功能事實仍一律回到 Anthropic 官方文件核對。

## 結論

貼文最可取的核心不是「提示詞已過時」，而是：可靠交付需要把目標、可驗證輸出、專案記憶、權限與隔離放進工作環境。Claude Code 官方確實建議以規格、測試／畫面／預期輸出及工具結果作為可檢查的回饋，並提供 `CLAUDE.md`、skills、hooks、subagents、worktrees 等組件；但它們不是一個官方命名的「四柱架構」，也不會自動保證正確或無人值守。([How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works), [Best practices](https://code.claude.com/docs/en/best-practices), [Hooks](https://code.claude.com/docs/en/hooks))

| 探索與規劃         | Plan Mode（`Shift+Tab` 或 `--permission-mode plan`）可讀檔及跑唯讀 shell command，不可改原始碼；`Ctrl+G` 可開啟 plan 編輯。([Best practices](https://code.claude.com/docs/en/best-practices), [Permission modes](https://code.claude.com/docs/en/permission-modes)) | 不是小修正的必要前置；使用者仍應審閱、修正並核准計畫。([Best practices](https://code.claude.com/docs/en/best-practices))                                                                                                                         |

## 經官方支持的文章主軸

適合 CarlStack 的文章不必重述 X 的章節，而可寫成：**「把 Claude Code 當成可驗證的開發迴圈，而不是一次性的 prompt」**。論證順序可如下：

1. **先交付契約，才交付指示。** 用 scope、既有來源／模式、預期輸出、非目標與驗證命令，降低模型自行猜測；官方把 tests、screenshots、expected output 與 command results 視為有效回饋。([How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works), [Best practices](https://code.claude.com/docs/en/best-practices))
2. **把一次性 context 外部化。** `CLAUDE.md` 保留穩定專案知識，plan／測試輸出／git diff 是可重開 session 的工件；不相關任務切 `/clear`，長任務在自然斷點 `/compact`。([Memory](https://code.claude.com/docs/en/memory), [Context window](https://code.claude.com/docs/en/context-window), [Sessions](https://code.claude.com/docs/en/sessions))
3. **把可靠度落在可觀測驗證。** Explore、Plan、Implement、Verify 讓查找、決策與改動分離；用測試與獨立 reviewer 取得證據，hook 只強制「未驗證不能停」的流程，而非替代判斷。([Best practices](https://code.claude.com/docs/en/best-practices), [Hooks](https://code.claude.com/docs/en/hooks))
4. **自治要有範圍。** 小而唯讀的探索可用 subagent；互不重疊的寫入才用 worktree；自動核准和非互動執行都應被權限、隔離與可回復的 Git 邊界包住。([Subagents](https://code.claude.com/docs/en/sub-agents), [Worktrees](https://code.claude.com/docs/en/worktrees), [Permission modes](https://code.claude.com/docs/en/permission-modes))

## 不可直接採用的說法

- 「每次指示都已過時」：官方支持的是 context、驗證、工具與持久指令要共同設計，並未宣告 prompt 無效。([How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works))
- 「長 session 必然失智」：可說無關 context 會降低表現；不可說有普遍、固定的衰退門檻。([Best practices](https://code.claude.com/docs/en/best-practices), [Context window](https://code.claude.com/docs/en/context-window))
- 「Stop hook 會驗證完成」：它能阻止停止、甚至執行 prompt／agent 判斷，但不是測試或人工審查的替代物，且需防止無限 loop。([Hooks](https://code.claude.com/docs/en/hooks))
- 「writer/reviewer、四柱、scope/source/pattern/symptom 是 Claude Code 官方方法」：它們可作為文章自訂框架，官方文件沒有將其定義為固定術語。([Subagents](https://code.claude.com/docs/en/sub-agents), [Memory](https://code.claude.com/docs/en/memory))
- 「auto mode 就是無人代理」：它只處理工具動作的核准分類；要跨 turn 持續執行是 `/goal`、`/loop`、背景或非互動 workflow 的另一件事。([Permission modes](https://code.claude.com/docs/en/permission-modes), [Goals](https://code.claude.com/docs/en/goal), [Commands](https://code.claude.com/docs/en/commands))
- 「checkpoint 可以放心取代 Git」：checkpoint 不含 Bash／外部修改，官方明確說它不是 Git 的替代品。([Checkpointing](https://code.claude.com/docs/en/checkpointing))
