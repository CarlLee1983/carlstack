## 一手資料核對

- [Three.js Fundamentals](https://threejs.org/manual/pages/fundamentals.html)：Three.js 自述為讓網頁 3D 更容易實作的 library；文件介紹 renderer、scene、camera、canvas 與 ES modules。支持它適合瀏覽器 3D 的定位，不代表它包含完整遊戲引擎或專案工具。
- [TypeScript Handbook：Everyday Types](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html)：說明型別分析與型別錯誤。型別檢查能攔住部分程式結構錯誤，不能證明畫面、碰撞或遊戲平衡正確。
- [Playwright Introduction](https://playwright.dev/docs/intro)、[Locators](https://playwright.dev/docs/locators)、[Screenshots](https://playwright.dev/docs/screenshots)：Playwright Test 是網頁端對端測試框架，可操作 Chromium、WebKit、Firefox，並能定位頁面元素及擷取瀏覽器畫面。測試仍須先定義可觀察的遊戲結果；擷取截圖本身不等於視覺正確性驗證。
- [MonoGame 官方入門文件](https://docs.monogame.net/articles/tutorials/building_2d_games/02_getting_started/)：文件稱 MonoGame 是融入 .NET 工作流的 framework，沒有內建遊戲製作 GUI，採 code-first 方式。它與 Three.js 的 Web 3D library 定位不同。
- [LÖVE 官方 GitHub repository](https://github.com/love2d/love)：官方說明其為 Lua 2D game framework，目標平台包括桌面及行動系統。它與 Three.js 的 3D 瀏覽器目標也不同。
- [Voxel Musou demo](https://voxel-musou.vercel.app/)：頁面標題為「赵云 — Voxel Musou」，頁面匯入本地 `three.module.js`。這只能確認 demo 使用 Three.js；沒有 Agent 或 TypeScript 的開發紀錄。
- [作者公開的 MonoGame／Godot 討論 Issue #44](https://github.com/cholf5/random/issues/44)：頁面標明分析文字由 ZCode + ark-code-latest 生成，討論的是 MonoGame 與 Godot 4 C#。它不是原貼文所引用 demo 的實作紀錄，也不是 Three.js、MonoGame、LÖVE 的對照實驗，本文不以此作為技術結論依據。

## 寫作判斷

官方文件能支持各工具的目標、輸入與執行方式，不能支持「Three.js + TypeScript 普遍最適合 Agent」的排名。文章主張應清楚標成工程推論：瀏覽器 3D 原型若同時具備快速建置、可控制輸入、可觀察狀態與可重跑的瀏覽器測試，Agent 的修改較容易形成短回饋迴路。TypeScript、npm 或 React 的存在本身，不等於驗證已完成。

選型建議採一個相同的小型玩法原型做本地比較，記錄首次可執行畫面的時間、首次可靠驗證互動的時間、Agent 交付後的人工修正量與重跑穩定性。這是團隊自己的決策實驗，不是已完成的框架 benchmark。需求若偏向 Lua 2D、原生桌面／行動部署或特定內容工作流，應依目標重新選型。
