## 主旨與中心論點

Bilgin Ibryam 認為，生成式 AI 可以快速產生實作，但不會替工程師決定產品是否值得做、正確行為、領域含義、架構與資料取捨、信任邊界、production 故障策略或交付成效。因此他以八本書整理這些仍需人類判斷的工程面向。

「AI 讓這八本書更重要」是作者的判斷，不是文章提出的實證研究；本文只能把它當成可檢查的工作假說，不能宣稱已證明因果關係。

## 可安全寫入文章的分析

1. 不應把八本書當成 AI coding 的前置閱讀清單；它們較適合轉成「這次變更缺哪種證據」的索引。
2. 每個變更不必完成八個問題。小型純文字修正可能不涉及資料相容或信任邊界，但應把不適用的理由說清楚。
3. 同一模型產生程式與測試不是獨立驗證。因此需要規格範例、既有 consumer、契約檢查、獨立 review 或 production 訊號提供不同來源的證據。
4. 最新 W3C Threat Modeling Guide 仍是 Group Note Draft；它可作結構參考，不應宣稱為已定案標準。
