## 建議文章角度

**公開產品上線前，不要求「安全」結論；要求七項可重跑、可失敗的驗收證據。**

這個角度不重述站內的 API 漏洞型錄或 Agent 權限治理，而是替使用 AI 快速完成網站的團隊定義一份最小安全證據包：誰測、在哪個環境、針對哪條業務不變量、得到什麼結果，以及什麼仍然不在覆蓋範圍。

## 原文內容（已核對）

X Article 顯示作者為蘇樂（[@ai_suxiaole](https://x.com/ai_suxiaole)），發布時間為 2026-09-06 20:49（頁面顯示時區）。原文主張「功能能跑」只證明正常操作可用，不能證明公開後仍能守住資料、計費與預算；它提出七個最低驗收結果：

1. 兩個一般帳號在沒有分享或明確授權時，不能互相讀取、修改或刪除資料。
2. 客戶端傳來的價格、角色、資源 ID 與額度不能改變後端判斷。
3. 餘額僅足一次時，併發或重複送出只能建立一份任務、扣一次費。
4. 重複或亂序的付款通知不會重複入帳，偽造或不相符的通知遭拒。
5. 註冊、上傳與 AI 呼叫有事先定義的次數、併發、用量或總成本上限。
6. 可取得的程式碼、日誌與網頁未洩漏憑證；已洩漏的憑證已撤銷與輪換。
7. 無法讀取的雲端、低代碼或 production 設定被明確列為未驗證。

原文同時要求把資料歸屬、使用者角色、免費與付費權限、計費與付款「只能一次」等規則先寫成安全不變量；動態測試只可在本機或明確獲准的測試環境進行，不能讀取真實使用者資料、打真實付款或產生實際費用。
