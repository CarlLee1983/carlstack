## 原文在說什麼

本文把 MCP 比作 AI 的 USB-C，依序介紹 Host、Client、Server，以及 Prompts、Resources、Tools。作者主張 MCP 能減少客製整合，並以本機檔案、資料庫、Slack 與程式執行為例，提醒工具需要權限控制。

可將 USB-C 類比保留為入門說明，但不能把「只要加上 MCP 就安全」寫成事實。MCP 定義互通介面，不替任何部署自動決定資料範圍、身分、授權、核准或稽核。

## 必須更正或限縮的地方

- MCP 2026-07-28 已轉向無 session、可由任一實例處理的 request/response 核心；舊的 HTTP+SSE transport 正在棄用期內。不可把 SSE 寫成遠端 MCP 唯一或主要的未來方式。
- Prompts、Resources、Tools 並非同一種「超能力」：規格分別標為 user-controlled、application-controlled、model-controlled。這是設計權責的起點，不是純名詞分類。
- server 位在資料前方，不會自動形成安全邊界。官方工具規格要求 server 驗證輸入、存取控制、限流與輸出清理；client 仍應讓使用者審查敏感操作、驗證結果、設 timeout 並留下 audit log。
- 本機 stdio 不等於資料永遠不會離開電腦；要看 host、模型供應商、server 實作與每一次 tool result 的資料流。文章不作絕對安全承諾。

| 可安全主張                                                                                             | 一手來源                                                                                          | 使用限制                                                     |
| ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Prompts、Resources、Tools 分別由使用者、應用程式、模型控制。                                           | [MCP Server Features](https://modelcontextprotocol.io/specification/2025-11-25/server/index)      | 這是協定角色，不是自動授權政策。                             |
| Tool schema 可描述輸入與輸出；server 必須驗證輸入、實作存取控制、限流、清理輸出。                      | [MCP Tools Specification](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)  | schema 不能替代業務授權或資料最小化。                        |
| 2026-07-28 將核心改為 stateless；舊 HTTP+SSE transport 已進入至少十二個月的棄用期。                    | [MCP 2026-07-28 release](https://blog.modelcontextprotocol.io/posts/2026-07-28/)                  | 客戶端與 server 的實際支援版本仍須各自確認。                 |
| HTTP authorization 使用 OAuth 2.1、受眾綁定與 token 驗證；stdio 不使用這一份 HTTP authorization flow。 | [MCP Authorization](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization) | OAuth 是傳輸與身分層的一部分，仍不決定每個 tool 的業務權限。 |

## 去重與文章角度

站內既有〈[MCP + MHS 會成為 AI 作業系統嗎？](../../src/content/blog/mcp-mhs-ai-operating-system.md)〉比較協定、driver 與作業系統；本篇應集中在初次導入 MCP 時的最小可用邊界：把「能發現」和「能執行」分開，並以 read-only 查詢工具與明確核准流程做第一個 production slice。兩篇互相連結。
