# 機制實驗室：用可操作的動態圖看懂 YouTube 類影音平台的三個機制

## Problem Statement

讀者在「設計 YouTube 類影音平台」這篇概念長文裡，能從文字與靜態圖理解結構，卻很難想像狀態如何流動：為什麼恢復連線的舊 worker 交出的轉碼產物會被拒絕、為什麼快取命中的媒體請求仍要驗證播放資格、為什麼命中率從 95% 掉到 70% 會讓回源變成六倍。靜態圖只能呈現某一刻，讀者得在腦中自己推演時間軸，最核心的論點因此容易被略讀過去。

## Solution

為這篇概念長文新增一個附屬的機制實驗室，網址為 `/blog/youtube-like-product-system-design/lab/`。實驗室收錄三張 anatomy 風格的等角動態圖，分別對應長文 §6 發布閘門、§7 播放授權、§8 回源成本。每張圖提供四個情境按鈕與一個重設按鈕；讀者按下情境，就看到該路徑上的零件動起來、即時讀數更新，最後出現兩三句「你剛剛看到了什麼」並連回長文對應章節。長文則在開頭放一個 callout，並在三張對應靜態圖下方放深連結，直接跳到實驗室的那張圖。

長文仍是閱讀概念的主體；實驗室只負責讓機制可以被操作與觀察，不重寫長文的論證。

## User Stories

1. 身為長文讀者，我想在文章開頭得知有配套的機制實驗室，以便決定是否邊讀邊操作。
2. 身為長文讀者，我想在 §6 的發布靜態圖下方找到通往實驗室同一機制的連結，以便在疑問產生的當下看它怎麼動。
3. 身為長文讀者，我想在 §7 的播放靜態圖下方找到對應的實驗室連結，以便觀察授權與位元組分流。
4. 身為長文讀者，我想在 §8 的回源靜態圖下方找到對應的實驗室連結，以便觀察快取未命中的成本放大。
5. 身為點擊深連結的讀者，我想直接落在實驗室中對應的那張圖，以便不必在頁面中尋找。
6. 身為實驗室讀者，我想在每張圖旁找到連回長文對應章節的連結，以便回去讀完整論證。
7. 身為實驗室讀者，我想在頁首看到一段導言說明如何操作與這頁的來源長文，以便知道從哪裡開始。
8. 身為實驗室讀者，我想在頁尾找到回到長文的連結，以便看完三張圖後繼續閱讀。
9. 身為從搜尋直接進入實驗室的讀者，我想不讀長文也能看懂每個情境發生了什麼，以便實驗室單獨成立。
10. 身為站內搜尋使用者，我想用相關關鍵字搜尋到機制實驗室，以便從搜尋找到它。
11. 身為 RSS 訂閱者，我不想在訂閱中看到沒有脈絡的實驗室頁面，以便訂閱內容只包含正式文章。
12. 身為瀏覽文章列表與系列導覽的讀者，我不想看到實驗室被當成一篇文章，以便列表與系列順序保持正確。
13. 身為讀者，我想在 §6 圖中按下「正常完成」，看見 worker 交件、通過驗證、播放資產指標切換，以便建立基準路徑的印象。
14. 身為讀者，我想在 §6 圖中按下「心跳中斷改派」，看見 worker A 失聯、租約到期、worker B 取得新 token，A 恢復後交件被閘門退回而 B 被接受，以便理解 fencing 規則。
15. 身為讀者，我想在 §6 圖中按下「重複完成通知」，看見閘門回傳原收據而指標不再切換，以便理解重複投遞不會產生第二次啟用。
16. 身為讀者，我想在 §6 圖中按下「來源損壞」，看見暫時讀取失敗以新的 attempt token 退避重試，一旦判定來源損壞就立即停止、工作進入有負責人的死信清單，以便分辨值得重試與應該停止的失敗。
17. 身為讀者，我想在 §6 讀數中看到有效 token、租約剩餘、目前 active asset ID 與收據狀態，以便把畫面對應到資料狀態。
18. 身為讀者，我想在 §7 圖中按下「正常播放」，看見應用只處理一次授權、之後的 segments 都由 CDN 提供，以便理解授權與位元組走不同的路。
19. 身為讀者，我想在 §7 圖中按下「到期前更新」，看見資格快到期時播放器回售票亭換新資格，以便理解短期資格的續期。
20. 身為讀者，我想在 §7 圖中按下「直接抓 segment URL」，看見沒有資格的請求在 edge 被拒絕、即使該 segment 已在快取，以便理解只保護 manifest 不夠。
21. 身為讀者，我想在 §7 圖中按下「授權服務暫時不可用」，看見已持資格的觀眾續播到資格到期、新觀眾無法開始，以便理解演練 C 的行為。
22. 身為讀者，我想在 §7 讀數中看到資格剩餘時間，以及應用請求數與 CDN 請求數的對照，以便看出兩條路的流量差距。
23. 身為讀者，我想在 §8 圖中切換「命中率 95%」與「命中率 70%」，看見總下行 10.4 Gbps 下回源從 0.52 Gbps 變成 3.12 Gbps，以便體會六倍差距。
24. 身為讀者，我想在 §8 圖中按下「冷門轉熱門」，先看見多個 edge 同時未命中造成回源暴衝，再看見啟用 Origin Shield 並合併並發回源後回源回落，以便理解共享回源快取的作用。
25. 身為讀者，我想在 §8 圖中按下「origin 超載」，看見基本畫質被保住、後補格式被暫緩，以便理解超載時的優先順序。
26. 身為讀者，我想在 §8 圖的 figure 內（含 figcaption）看到「位元組比例，非 request hit ratio」的註記，以便不誤讀命中率的意義。
27. 身為讀者，我想在每個情境播完後看到兩三句說明剛剛發生了什麼，以便確認自己看懂了。
28. 身為讀者，我想按下重設回到圖的初始狀態，以便重新操作或比較不同情境。
29. 身為讀者，我想在情境播放途中改按另一個情境時圖能乾淨地切換，以便不出現殘留或錯亂的狀態。
30. 身為鍵盤使用者，我想用 Tab 與 Enter／Space 操作所有情境與重設按鈕，並看見清楚的焦點樣式，以便不依賴滑鼠。
31. 身為螢幕閱讀器使用者，我想在按下情境後聽到讀數與說明的更新，以便取得與視覺使用者相同的結果。
32. 身為螢幕閱讀器使用者，我想讓每張圖有可讀的標題與描述，以便理解圖所代表的實物比喻。
33. 身為偏好減少動態效果的讀者，我想讓情境直接跳到結果狀態但仍回應我的操作，以便降低視覺干擾又不失去功能。
34. 身為停用 JavaScript 的讀者，我想仍看到完整可讀的靜態圖，以便理解各零件與流向。
35. 身為手機讀者，我想在 320 px 寬度下辨認每張圖的主要零件並操作按鈕，以便在小螢幕使用實驗室。
36. 身為深色模式讀者，我想讓圖的顏色與頁面主題一致且文字對比足夠，以便舒適閱讀。
37. 身為切換主題的讀者，我想讓已顯示的圖即時套用新主題，以便不用重新整理頁面。
38. 身為使用低階手機的讀者，我想讓捲出畫面的圖停止動畫，以便不浪費電力與效能。
39. 身為分享連結的讀者，我想讓實驗室頁面在社群預覽中顯示長文封面與明確標題，以便收件者知道它屬於哪篇文章。
40. 身為長文的既有讀者，我想讓長文網址與內容保持可用，只多出通往實驗室的連結，以便原本的書籤與引用不受影響。
41. 身為作者，我想讓長文論點（例如舊 token 的產物不能發布）由自動測試守住，以便日後修改圖的情境時不會悄悄違背文章主張。
42. 身為作者，我想讓這個「概念長文配機制實驗室」的模式有明確的網址慣例與決策記錄，以便第二篇實驗室照同一規則建立。
43. 身為維護者，我想在圖解規範中找到機制實驗室的互動規則，以便新增或修改實驗室時有一致的標準。

## Implementation Decisions

- 用語：「概念長文」與「機制實驗室」依專案 CONTEXT 文件的定義；決策依 ADR 0008（概念長文可附一個機制實驗室，網址為 `/blog/<slug>/lab/`）。
- 路由：以靜態路由頁面實作本篇的實驗室，網址 `/blog/youtube-like-product-system-design/lab/`，維持 `trailingSlash: "always"`。它在 Astro 路由優先順序中高於文章的 rest 參數路由，與既有的分頁路由並存方式相同。第一版不做通用的動態實驗室路由，也不新增 content collection 或 frontmatter 欄位。
- 版型：實驗室頁直接使用 BaseLayout，不使用需要 collection entry 的 ArticleLayout。保留預設的 Pagefind 收錄與 sitemap 收錄；不加入 RSS、文章列表、系列導覽、首頁。標題為「機制實驗室：設計 YouTube 類影音平台」，Open Graph 圖沿用長文封面，canonical 指向自身。
- 頁面結構：頁首導言（操作方式＋連回長文）→ 三張圖依長文順序 → 頁尾回到長文。三張圖的錨點固定為手寫英文 id：`publish-gate`、`playback-auth`、`origin-cost`；這些錨點屬於對外網址契約，不依賴由中文標題自動產生的 heading id。
- 長文修改：開頭加入一個指向實驗室的 callout；§6、§7、§8 的對應靜態圖下方各加一個深連結指向上述錨點；更新 `updatedDate`。依 ADR 0007，文章會因更新日回到列表頂端。
- 情境模組（唯一的新測試接點）：一個純函式模組，對外提供統一介面 `play(mechanism, scenarioId)`，回傳該情境的步驟序列。每一步的形狀固定為：`state`（該機制各零件的狀態）、`readout`（即時讀數）、`caption`（僅最後一步，兩三句說明）。另提供各機制的情境清單（id、按鈕標籤）與初始狀態，供重設使用。模組不碰 DOM、不碰 Astro API、不讀時鐘。
  - `mechanism` 為 `publish-gate`、`playback-auth`、`origin-cost` 三者之一。
  - publish-gate 情境：正常完成、心跳中斷改派、重複完成通知、來源損壞。讀數：有效 token、租約剩餘、active asset ID、收據狀態。
  - playback-auth 情境：正常播放、到期前更新、直接抓 segment URL、授權服務暫時不可用。讀數：資格剩餘時間（示例效期五分鐘）、應用請求數、CDN 請求數。
  - origin-cost 情境：命中率 95%、命中率 70%、冷門轉熱門、origin 超載。讀數：位元組命中率、回源 Gbps、origin 負載。數字沿用長文：總下行 10.4 Gbps，95% → 0.52 Gbps，70% → 3.12 Gbps。
- 圖元件：三個文章專屬的一次性 Diagram 元件，命名遵循既有 `<Topic>Diagram` 慣例。實物比喻：publish-gate 為「驗印閘門」（兩條輸送臂代表 worker A／B，產物匣蓋 generation 與 attempt token 戳記，刻度盤顯示有效 token 與租約倒數，拉桿代表播放資產指標）；playback-auth 為「售票亭＋輸送管」（售票亭為播放 API，發出附沙漏的短期資格；CDN edge 槽經驗票口流向播放器；origin 只能經 CDN 進入）；origin-cost 為「水塔＋抽水站」（edge 水塔、origin 抽水站、可加入的 Origin Shield 蓄水池）。
- 圖的產製：在 repo 外以 anatomy skill 產出靜態 SVG，直接寫入元件模板（不經 `set:html`），元件標頭註解記錄概念到實物的對應與 anatomy skill 的 commit。互動由元件內的 vanilla `<script>` 呼叫情境模組，依步驟切換既有 SVG 元素的 class、transform 與讀數文字完成。不 commit anatomy kit，不使用 WebGL 或 3D 模式，不引入 UI framework 或新的 npm 相依。
- 圖的規範：完全遵守圖解規範的 anatomy 章節——Figure 尺寸（40–80 零件）、單一縮放版面且 320 px 可辨識主要零件、標題／提示／讀數移入 `figcaption`、`--anatomy-*` 由 `--dg-*` token 重新定義、深色模式只透過解析後的 `data-theme`（ADR 0005）、SVG 內文字至少 12.5 px、文字與底框對比至少 3.0。
- 互動規則（新增到圖解規範的「機制實驗室」小節）：
  1. 情境與重設按鈕是 SVG 外的原生 `<button>`，支援鍵盤並套用 `:focus-visible`。
  2. 讀數與情境說明位於 `aria-live="polite"` 區域。
  3. 每張圖都有重設按鈕。
  - 另依 anatomy 動態規範：reduced-motion 時直接跳到每步目標狀態但仍回應操作；以 IntersectionObserver（讀最新 entry）在圖離開畫面時停止動畫；情境播放中切換情境會先取消進行中的動畫再開始新情境；停用 JS 時靜態 SVG 完整可讀。
- 架構文件：URL 形狀邊界列加入 `/blog/<slug>/lab/`，並連到 ADR 0008。

## Testing Decisions

- 好的測試只透過情境模組的公開介面 `play(mechanism, scenarioId)` 與情境清單驗證外部行為：給定情境，斷言步驟序列的終態與關鍵讀數，代表長文的論點。不斷言中間步驟的數量、動畫時間或內部資料結構，讓情境的動畫拆分可以自由調整。
- 受測模組：只有情境模組。斷言至少包含：
  - publish-gate「心跳中斷改派」終態為 A 的產物被拒絕、B 的產物被接受且指標指向 B 的資產；「重複完成通知」回傳原收據且指標只切換一次；「來源損壞」中每次重試使用不同的 attempt token，判定來源損壞後立即停止並進入死信清單，指標不變。
  - playback-auth「直接抓 segment URL」即使快取命中仍被 edge 拒絕；「授權服務暫時不可用」中持有效資格的觀眾可續播、新觀眾無法開始；「正常播放」應用請求數遠少於 CDN 請求數。
  - origin-cost 命中率 95% 時回源為 0.52 Gbps、70% 時為 3.12 Gbps；「冷門轉熱門」啟用 Shield 與合併回源後的回源量低於啟用前；「origin 超載」終態保住基本畫質、暫緩後補格式。
  - 每個機制的每個情境 id 都能播放、最後一步帶有 caption，未知的 mechanism 或 scenarioId 會丟出錯誤。
- 前例：既有的 `tests/*.test.ts` 以 `node --experimental-strip-types --test` 測試 `src/utils` 的純函式（如 content、featured、toc、share），新測試沿用相同寫法並由 `pnpm test` 執行。
- 頁面能否建置由既有 `pnpm check` 守住；`pnpm content:policy -- <base>` 檢查修改過的長文。
- 不新增建置產物或 DOM 層級的自動測試（專案無此前例）。以下依 `docs/testing.md` 手動驗證：桌面與 320 px、淺色與深色下三張圖的外觀與按鈕操作；長文三個深連結與實驗室錨點對得上；reduced-motion 與停用 JS 的呈現；鍵盤與螢幕閱讀器的讀數宣告。

## Out of Scope

- 長文 §5 斷點續傳、§10 下架、§11 故障演練的動態圖，留待第一版上線後再評估。
- 通用的實驗室動態路由、content collection、frontmatter 欄位或自動入口元件；等第二個實驗室出現時再決定（ADR 0008 已記錄觸發條件）。
- 參數滑桿或讓讀者自由輸入數值的模擬。
- WebGL、3D 模式、執行期重建幾何、把 anatomy kit 放進 repo。
- 為實驗室製作新封面圖。
- 其他文章的實驗室。
