# 主題詞雲：以文章標籤探索 CarlStack 主題

## Problem Statement

讀者目前可以在標籤總覽找到所有主題，但很難快速看出哪些主題累積了較多文章。讀者若想從主題分布開始探索，現有的標籤清單缺少直觀的視覺入口。

## Solution

新增獨立的「主題詞雲」頁面。詞的大小代表該標籤關聯的已發布文章數；點擊詞可進入既有標籤文章頁。頁面同時提供完整、可使用鍵盤操作的標籤清單。現有標籤總覽與標籤文章頁繼續提供原有導覽功能。

## User Stories

1. 身為讀者，我想從標籤總覽進入主題詞雲，以便用另一種方式探索文章。
2. 身為讀者，我想一眼看見文章較多的主題，以便了解 CarlStack 的內容重心。
3. 身為讀者，我想知道詞的大小代表什麼，以便正確解讀視覺化結果。
4. 身為讀者，我想看見詞雲涵蓋的標籤範圍，以便知道它是否顯示全部標籤。
5. 身為讀者，我想點擊詞雲中的標籤，以便閱讀該標籤下的文章。
6. 身為讀者，我想在圖表旁找到所有標籤及其文章數，以便精確查找主題。
7. 身為讀者，我想讓文字清單中的每個標籤通往相同的標籤文章頁，以便選用熟悉的導覽方式。
8. 身為鍵盤使用者，我想透過一般連結完成所有標籤導覽，以便不依賴圖表的滑鼠互動。
9. 身為螢幕閱讀器使用者，我想取得標籤名稱、文章數和連結，以便理解並使用主題導覽。
10. 身為停用 JavaScript 的讀者，我想仍能看到完整標籤清單，以便繼續探索文章。
11. 身為網路不穩定的讀者，我想在圖表載入失敗時仍可使用清單，以便不被載入錯誤阻斷。
12. 身為手機讀者，我想在 320 px 寬度看清詞雲並操作文字清單，以便在小螢幕探索主題。
13. 身為使用深色模式的讀者，我想讓詞雲顏色與頁面一致且清楚可讀，以便舒適閱讀。
14. 身為切換主題模式的讀者，我想讓已顯示的詞雲更新顏色，以便不用重新整理頁面。
15. 身為偏好減少動態效果的讀者，我想避免詞雲的佈局動畫，以便降低視覺干擾。
16. 身為讀者，我想在標籤數不足 40 個時看到所有標籤，以便不遺漏主題。
17. 身為讀者，我想在沒有已發布標籤時看到清楚的空狀態，以便知道頁面目前沒有資料。
18. 身為既有網站讀者，我想讓目前的標籤總覽與標籤文章頁保持可用，以便原本的書籤和使用方式繼續有效。
19. 身為瀏覽其他頁面的讀者，我想讓詞雲程式只在詞雲頁面載入，以便其他頁面維持既有載入成本。
20. 身為內容編輯者，我想讓詞雲隨已發布文章的標籤自動更新，以便不必另行維護主題清單。

## Implementation Decisions

- 新頁面的公開路由為 `/explore/wordcloud/`；標籤總覽提供入口。第一版不增加全站主導覽項目。
- Content Collections 仍是文章與標籤的唯一資料來源。頁面沿用現有 Collection 存取入口取得可見文章及 taxonomy，不建立第二份分類資料，也不更動內容 schema。
- 每個詞的權重是對應標籤的文章數，不是文章全文詞頻。正式建置只統計已發布文章；沿用既有開發環境的草稿可見規則。
- 詞雲選取文章數最多的 40 個標籤；同數量時依標籤名稱穩定排序。若總數少於 40，全部顯示。頁面明示圖表的前 40 名範圍；完整 HTML 清單列出所有標籤。
- 詞雲和完整清單使用同一份建置期 taxonomy 資料。標籤名稱、文章數和 URL 不各自重算；點擊圖上的詞或清單連結均前往既有 `/tags/<slug>/`。
- 以 `echarts-wordcloud` 2.x 與其宣告支援的 ECharts 5 實作圖表。瀏覽器端初始化只在新頁面執行，圖表程式不進入全站共用版型。導入時確認套件授權及鎖定版本。
- 完整 HTML 清單是可操作的內容；詞雲是補充視覺入口。圖表載入失敗或 JavaScript 停用時，清單仍可使用。螢幕閱讀器不需要重複讀取同一批圖表詞。
- 圖表顏色取自現有 design tokens，依網站解析後的深淺色狀態更新；容器尺寸變動時重新排版，並遵守降低動態效果偏好。
- 空資料時顯示與網站相符的空狀態，不初始化空白圖表。既有標籤 slug 與公開 URL 保持不變。
- 此功能維持靜態建置與純前端互動；不增加資料庫、後端 API 或新的內容寫入流程，符合既有內容來源 ADR。

## Testing Decisions

- 測試以讀者能觀察的結果為準：頁面是否出現、顯示哪些標籤與文章數、連結導向何處，以及停用 JavaScript 後能否導覽。避免測試 ECharts 的內部 option 結構或繪圖演算法。
- 主要驗收邊界是**建置後的詞雲頁面**：檢查靜態 HTML 有完整標籤連結與正確計數，公開入口和目標路由存在。這是新增功能需要的最高層級測試接縫；不為圖表另建一組底層測試 API。
- 既有內容測試已覆蓋草稿過濾、taxonomy 正規化，以及文章數排序與同數量時的穩定排序。若實作抽出新的純資料轉換規則，沿用相同測試風格，驗證其可觀察結果及不修改輸入。
- 瀏覽器驗收涵蓋圖表點擊、圖表載入失敗時的清單、深淺色切換、尺寸變化、降低動態效果偏好，以及桌面與 320 px 視窗。現有專案沒有 E2E 或視覺回歸框架，這些互動與視覺條件以實際頁面檢查。
- 檢查其他頁面未載入 ECharts 與詞雲程式。執行專案既有 `pnpm check`、`pnpm test` 及適用的內容 policy gate。

## Out of Scope

- 從文章全文擷取關鍵字、中文斷詞、TF-IDF 或其他文字分析。
- 使用者自訂日期、篩選條件、詞雲形狀或權重算法。
- 改動既有標籤總覽的列表、標籤文章頁、taxonomy URL、內容 schema 或全站主導覽。
- 導入 ECharts 6；目前詞雲套件的 peer dependency 僅宣告 ECharts 5。

- 專案架構要求 `src/content` 為內容唯一來源，並以 Astro 建置純靜態 HTML；[架構文件](https://github.com/CarlLee1983/carlstack/blob/main/docs/architecture.md)與[內容來源 ADR](https://github.com/CarlLee1983/carlstack/blob/main/docs/adr/0003-git-content-as-source-of-truth.md)約束此功能。
- 網站目前以解析後的 `data-theme` 決定深淺色；[主題 ADR](https://github.com/CarlLee1983/carlstack/blob/main/docs/adr/0005-diagram-dark-mode-selector.md)約束圖表配色方式。
- [`echarts-wordcloud` README](https://github.com/ecomfe/echarts-wordcloud)說明其安裝與互動用法；[套件宣告](https://github.com/ecomfe/echarts-wordcloud/blob/master/package.json)列出 ISC 授權與 ECharts 5 peer dependency。
- 專案目前沒有 `proposed` 狀態的 ADR。此規格只定義新功能，尚未實作。
