「Claude 會記住」與「讓 Claude 定期做」看起來像是個人工作流開始複利的訊號：前者減少每次重述背景，後者消除重複啟動工作。但兩者只提供持久性與觸發器，不會自動保證取回的內容正確、任務仍符合現況，或輸出真的可用。

[@ery_treasure 的原始貼文](https://x.com/ery_treasure/status/2094935658339213554)把 Claude 的記憶與排程放進同一個工作習慣；本文不把貼文的個人做法當成產品保證，而是把它轉成可檢查的最小閉環。

## 先分清楚：記憶保存脈絡，排程重跑工作

Claude 的專案、全域或工作區脈絡能降低重新說明背景的成本；排程任務則會依保存的指令，在指定節奏建立獨立的執行。Anthropic 也提醒，排程任務即使電腦不在線仍可執行，並應定期檢視每一次結果與停用不再使用的任務。[Claude Cowork 文件](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork)

因此不應把它們混成「AI 自己記得該做什麼」：

| 能力           | 真正解決的問題                     | 不會自動解決的問題                       |
| -------------- | ---------------------------------- | ---------------------------------------- |
| 記憶／持久脈絡 | 下次任務較容易取得背景、偏好與規則 | 背景是否仍正確、此輪是否取回了相關內容   |
| 排程           | 在時間點重跑明確任務               | 輸入是否更新、輸出是否正確、行動是否安全 |

產品可用的記憶範圍、排程與連接器權限會隨方案、工作區設定與介面演進而不同；建立工作流前，應以當下產品設定與官方文件為準，而不是依賴一次性的截圖或貼文描述。

## 用一張任務卡取代「每天幫我整理」

要讓排程可交接，任務至少要有穩定輸入、有限產物與驗收點。例如每週研究摘要可以先寫成：

```yaml
input: 過去七天、指定資料夾與已授權的唯讀來源
output: 一份含來源連結的 Markdown 摘要
acceptance:
  - 每個事實保留原始來源
  - 不足資料時明確標示「無法判定」
  - 不寫入、寄送或發布外部系統
review: 每週一由人檢查並決定是否採用
```

這比補長 prompt 更重要：它限制任務的資料邊界，也讓人能分辨「本次沒有新訊號」與「Agent 漏掉了訊號」。如果工作需要寄信、改動檔案、付款或發布，產物應先停在草稿或待核准清單；不要讓定期觸發直接跨過不可逆操作。

> [!WARNING]
> 背景任務讀到網頁、信件或文件時，仍可能遇到 prompt injection。高權限連接器、敏感檔案與外部寫入應分開授權，並將人工核准放在動作前，而非只在事後看摘要。

## 複利來自被驗證的回寫

每輪不需要留下完整對話，只需保留能讓下一輪判斷的 receipt：輸入範圍、使用來源、產物位置、驗收結果與例外。下一輪的 Claude 再從已核准的摘要或規則取用，而不是把所有歷史輸出無差別塞進 context。

可用一個小型對照實驗驗證它是否真的有用：連續四週記錄「人工修正數」、「無法判定但硬下結論的次數」、「從觸發到可採用輸出的時間」。若加入記憶或排程後，這些指標沒有改善，就先刪除過期脈絡、縮小任務輸入或停用排程；不需要再疊一層 Agent。

## 最小可靠版本

1. 只挑一個低風險、輸出可人工檢閱的定期任務。
2. 用任務卡定義來源、產物、禁止動作與驗收。
3. 每次執行保存 receipt，錯誤只在通過 review 後才寫回持久脈絡。
4. 連續幾輪能穩定減少人工整理後，才增加頻率、資料源或自動化範圍。

記憶讓工作不必每次從零開始；排程讓工作可以準時開始。真正能累積的部分，仍是每次輸出有來源、有驗收、能被錯誤更正的外部制品。
