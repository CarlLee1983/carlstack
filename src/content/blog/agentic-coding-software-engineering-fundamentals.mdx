「既然 AI 都能自己寫 Code、修 Bug 甚至跑測試了，工程師還需要學資料結構、系統架構和設計模式嗎？」

這是近來技術社群經常討論的問題。隨著「Vibe Coding」概念流行，許多人只要用自然語言給出指示，就能很快看見一個可運作的 Web 應用。

然而，當這些 Demo 試圖走進生產環境，面對真實世界的高併發、資料一致性要求、安全性審計與持續迭代時，脆弱性便一覽無遺。

[Andrew Ng（吳恩達）在「AI Engineering Skills Map：Software Engineering Fundamentals」中提出更精確的說法](https://x.com/andrewyng/status/2093388974194872781)：即使 Coding Agent 撰寫全部程式碼，工程師仍要理解可選的權衡，才能把 Agent 導向符合應用情境的決策。

原文將這部分能力拆成五項：全端應用、資料管理、系統架構、安全與可靠性，以及 production 的擴展與維運；並點出 Vibe Coding 容易忽略延遲、可用性、一致性、可靠性、可維護性、簡單性與成本之間的取捨。

## 貶值與升值：工程師的能力再平衡

| 邊際價值大幅下降的能力        | 邊際價值呈指數上升的能力                                   |
| ----------------------------- | ---------------------------------------------------------- |
| 死背特定語言的 API 與語法細節 | **系統架構判斷**（選擇單體 vs. 模組化、選擇正確的資料流）  |
| 手工撰寫繁瑣的 CRUD 樣板代碼  | **可驗證性設計**（撰寫能作為 Agent 驗收標準的嚴密測試）    |
| 重複性代碼搬運與手動格式調整  | **失敗模式預判**（預判併發、網路中斷、安全漏洞與邊界條件） |

## 結語：回歸問題解決的本質

軟體工程的本質從來都不是「在編輯器裡敲進字元」，而是**在複雜的約束條件下，構建可預測、可維護且能解決真實問題的系統**。Agent 能代替部分實作，但不會自動知道資料生命週期、架構邊界或可接受的營運風險。

當編寫程式碼的阻力被 AI 降低，紮實工程基本功就成為槓桿：它讓開發者能更快把清晰的架構思考轉化為可驗證的生產級軟體。
