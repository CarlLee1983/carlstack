Ruby on Rails 創始人、37signals 共同創辦人 David Heinemeier Hansson（DHH）在 2025 年推出 Linux 發行版 [Omarchy](https://omarchy.org/manual/)，2026 年 8 月發布 4.0 版。

這不是 DHH 第一次嘗試打造開發者專屬的工作環境。早在 2024 年，他就曾推出基於 Ubuntu 和 GNOME 的自動化設定腳本 [Omakub](https://github.com/basecamp/omakub)。然而，Omakub 最終被宣布退役，取而代之的是獨立且完整的發行版 Omarchy（見 [omarchy.org/omakub](https://omarchy.org/omakub)）。

DHH 為什麼從「寫腳本客製既有發行版」，走到「親自打包一個基於 Arch Linux 的發行版」？它標榜的「AI-Native（以 AI Agent 為一等公民）」又怎麼運作？下面依序看系統架構、互動設計、AI 整合，最後評估誰適合用。

---

## 一、從 Omakub 到 Omarchy：DHH 的「主廚精選（Omakase）」哲學

「Omakase（お任せ）」是日本料理的主廚精選：客人不看菜單逐項點菜，交給主廚決定食材、風味搭配與上菜順序。

在軟體工程上，DHH 一向擁護這套做法，Ruby on Rails 預設整合 Active Record、Stimulus、Turbo 就是例子。Linux 桌面則很難找到這種由人替你選好的組合，常見的選擇分成兩個極端：

- **傳統 Linux 桌面的兩極**：
  - **開箱即用型（如 Ubuntu、Fedora）**：預設封裝完整，但常附帶厚重的桌面環境（如 GNOME/KDE）和預設套件包袱（如 Snap），視窗排版邏輯也很難完全客製。
  - **自己動手型（如原生 Arch Linux、Gentoo）**：使用者幾乎什麼都能改，代價是從驅動程式、音訊伺服器（PipeWire）、顯示伺服器（Wayland）、平鋪視窗管理器（Hyprland/i3）到每一份 dotfiles 都要逐一手動調整，除錯常花上數週。

### 核心驅動力：美感是動力的源頭

DHH 在官方手冊裡寫道：_「A beautiful system is a motivating system, and productivity has always been downstream from motivation.（美感激發動力，而生產力源於動力。）」_

Omarchy 不打算做成適合所有人的通用 Linux，它的定位是一套**「零冗餘（Zero Bloat）、現代化、全鍵盤驅動且具備統一美學的專業開發者工作站」**。

## 二、技術架構：Arch Linux、Hyprland 與 Quickshell 的三層組合

Omarchy 不用傳統發行版常見的重量級桌面環境（如 GNOME、KDE Plasma），改用 Wayland 生態裡的輕量組合：

| 架構層級                         | 選型技術           | 選型原因與工程優勢                                                                                                                                                                                                         |
| :------------------------------- | :----------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **基礎系統 (Base OS)**           | **Arch Linux**     | 滾動更新（Rolling Release），隨時拿到最新核心與驅動；Pacman 與 AUR 生態；安裝預設啟用 **LUKS 全磁碟加密** 與 **Btrfs 系統快照**。                                                                                          |
| **視窗合成器 (Compositor)**      | **Hyprland**       | 基於 Wayland 的動態平鋪視窗管理器，具備流暢的 GPU 硬體加速動畫、靈活的浮動／平鋪混排規則與多螢幕動態工作區。                                                                                                               |
| **桌面介面 (Desktop Shell)**     | **Quickshell**     | 以 QML 與 C++ 寫成的桌面建構套件，4.0 起取代先前的 Waybar，整合頂部狀態列、控制面板與微互動。                                                                                                                              |
| **核心終端 (Terminal & Editor)** | **Foot + LazyVim** | 4.0 起預設終端機改為輕量的 Foot（[v4.0.0 release notes](https://github.com/basecamp/omarchy/releases/tag/v4.0.0)），Alacritty 是 3.x 的預設，現在和 Ghostty、Kitty 一樣是選項；搭配預先設定好的 Neovim (LazyVim) 與 Tmux。 |
| **系統管理 (System CLI)**        | **`omarchy` CLI**  | 自製整合命令列工具，統一管理主題更換、套件升級、顯示器設定與環境診斷。                                                                                                                                                     |

### 為什麼選擇 Quickshell 而非傳統 Waybar？

在傳統 Hyprland dotfiles 社群中，多數使用者採用 `Waybar` 或 `Eww` 撰寫狀態列。Waybar 的動態狀態不好管理，CSS 排版也受限；Eww 用自製的 Yuck 語法，維護成本較高。

Omarchy 4.0 改用 [Quickshell](https://quickshell.org/) 重寫整個桌面 shell，[v4.0.0 release notes](https://github.com/basecamp/omarchy/releases/tag/v4.0.0)（2026-08-14）列出 Waybar、Walker、Mako、SwayOSD 等元件全數移除。Quickshell 利用 Qt/QML 成熟的宣告式 UI 架構與事件驅動模型，讓桌面面板像前端應用一樣即時反應系統事件（如音量變化、網路頻寬波形），介面可以做得更細，也更容易擴充。

## 三、純鍵盤操作

Omarchy 的日常操作完全圍繞**「雙手不離開鍵盤」**設計：

1. **空間化工作區（Dynamic Workspaces）**：
   用 `Super + 1~9` 切換工作區。視窗自動依二元樹或螺旋結構平鋪，不必再用滑鼠拖曳、縮放、對齊視窗。
2. **統一剪貼簿與搜尋歷史（Unified Clipboard & History）**：
   剪貼簿管理整合在系統裡，隨時叫出歷史紀錄搜尋文字、圖片或程式碼片段，切換 Context 時不會弄丟剛複製的內容。
3. **文字 OCR 與語音聽寫（Text Extraction & Dictation）**：
   一鍵選取螢幕任意區域即時執行 OCR 辨識並複製至剪貼簿。語音聽寫不是預裝功能：[4.0.2 手冊](https://github.com/basecamp/omarchy/blob/v4.0.2/manual/11-text-extraction-dictation.md)寫的是從 _Install > AI > Dictation_ 另外安裝 Voxtype，預設載入本機的英文基礎模型。文章發布後，新版手冊改以使用雲端處理的 Superwhisper 為新安裝的預設。
4. **全域主題同步機制（Unified Theming Engine）**：
   內建 Tokyo Night、Catppuccin、Gruvbox、Rose Pine、Everforest、Nord 等知名配色。透過 `omarchy theme set <name>` 或圖形選擇器，能**單鍵即時同步**更新 Hyprland 邊框、Quickshell 狀態列、終端機、Neovim 編輯器與桌布，整個桌面的配色保持一致。

## 四、AI-Native：將 AI Agent 視為作業系統「一等公民」

4.0 "Quattro" 版本的主軸是用 Quickshell 重寫桌面 shell；[v4.0.0 release notes](https://github.com/basecamp/omarchy/releases/tag/v4.0.0) 的重點功能裡，另有一項是可設定預設 Coding Agent，附快捷鍵啟動與當機診斷。

傳統作業系統把 AI 工具當成「第三方安裝的 CLI 指令」，Omarchy 則把 Agent 當成作業系統基礎設施的一部分：

### 1. 延遲載入啟動器（Lazy-Loaded Launchers）

Omarchy 預裝了目前主流 Coding Agent（包括 Claude Code、OpenAI Codex、OpenCode、GitHub Copilot、Grok 等）的輕量啟動 Stub。系統映像檔不預載數百 MB 的執行期與相依套件，使用者第一次在終端機輸入指令或按下快捷鍵時，才自動下載最新版本並快取。

### 2. 頂部狀態列專屬 Agents 面板

依 [4.0.2 手冊](https://github.com/basecamp/omarchy/blob/v4.0.2/manual/17-ai.md)，Omarchy 第一次在機器上發現 AI coding 的使用紀錄後，頂部狀態列會多出 Agents 圖示，之後就一直留著。圖示背後的面板顯示：

- 訂閱方案，以及 5 小時與每週額度的使用百分比（預付制則顯示剩餘餘額）
- 按日、按模型統計的 Token 用量，內建支援 Claude Code、Codex 與 Fireworks

這些用量紀錄由 `omarchy agent usage-update` 每 15 分鐘重新產生一次，不是即時數字。

### 3. 作業系統級 Agent Skills

Omarchy 為 AI Agent 提供標準化的系統控制介面（Skills），Agent 除了幫你寫業務程式碼，也能操作 OS 本身：

```bash
# 讓預設 Agent 直接執行一段任務，搭配 Omarchy skill 調整工作環境
omarchy agent prompt "幫我把目前主題切換為 Gruvbox，並把主螢幕旋轉為垂直排列"
```

Omarchy 內建一個調整系統用的預設 skill，可以改 Hyprland 設定、調整狀態列，甚至從頭做一套主題；`omarchy` CLI 也特別適合讓 Agent 呼叫。手冊把這個 skill 標為實驗性：建議先用 plan mode 看 Agent 打算改什麼，並準備好回復變更，必要時用 `omarchy reinstall configs` 重設設定檔。

> [!NOTE]
> **安全與隱私考量**：Agent CLI 通常能存取終端機與環境變數，授予 Agent 自動執行權限（如 `--dangerously-skip-permissions`）前，要評估機密資料外洩的風險。

## 六、誰適合用 Omarchy？

### 推薦採用族群

1. **重度鍵盤流與 TUI 愛好者**：已經習慣 Vim/Neovim、Tmux 與快捷鍵導向，想擺脫滑鼠拖曳視窗的工程師。
2. **想體驗 Arch + Hyprland 但不想無止境踩坑的人**：省下設定 Wayland 驅動、音訊、字型渲染、狀態列與處理快捷鍵衝突的數百小時，直接拿到調好的環境。
3. **AI-Assisted 開發者**：重度依賴 Coding Agent，希望終端機、編輯器與系統層都整合好 AI。

### 需要先評估的情況

- **強烈依賴 macOS / Windows 專有軟體者**：如 Adobe 全家桶、部分特殊企業內部 VPN 或特定 CAD 工具（即便有內建 Windows VM，體驗仍不及原生）。
- **從零 DIY 的玩家**：如果你喜歡每個 config 檔都自己從零寫，對每個套件都有很強的自訂需求，Omarchy 強烈的「主廚意志」可能和你的習慣衝突。

## 七、總結

Omarchy 示範了**「自由度極高的 Arch Linux」**和**「精心調校的開箱即用體驗」**可以並存。

它把 **Arch Linux 的新鮮度**、**Hyprland 的流暢動態**、**Quickshell 的現代介面** 與 **AI Agent 的系統級整合** 放進同一套系統，給軟體工程師一個兼顧效率與美感的工作台。

如果你在找一套能提振工作動力、以鍵盤和 AI 輔助為主的開發環境，[Omarchy Manual](https://omarchy.org/manual/) 值得一讀。

想從 DHH 最近的訪談理解他如何把這套產品觀延伸到 Agent 工作流，可閱讀 [DHH 談 Agentic Engineering：當實作不再稀缺，決策如何成為工程瓶頸](/blog/dhh-agentic-engineering-podcast/)。
