## 2. 核心特徵工程（Real-Time Feature Engineering）

特徵更新延遲與缺失會改變模型的輸入分布。評估時需同時記錄辨識表現、特徵新鮮度與缺失率。

### 2.1 三大特徵維度矩陣

| 特徵類型         | 計算時效       | 特徵範例                                             | 儲存載體                         |
| :--------------- | :------------- | :--------------------------------------------------- | :------------------------------- |
| **靜態特徵**     | 離線天級更新   | 用戶註冊年資、歷史信用評級、實名認證狀態             | PostgreSQL / DynamoDB            |
| **動態即時特徵** | 毫秒/分鐘級    | 同一 IP 過去 5 分鐘下單次數、過去 1 小時切換卡號數量 | Redis 滑動視窗 / Flink State     |
| **關聯圖譜特徵** | 近即時（秒級） | 與該設備共享相同收貨地址的歷史詐欺帳號數量           | 圖資料庫（Neo4j / Nebula Graph） |

### 2.2 Redis 滑動視窗統計實作

Redis `ZSET` 可儲存每台裝置近 10 分鐘的失敗事件。score 使用毫秒時間戳，member 使用穩定且唯一的事件 ID，避免同毫秒兩筆事件被合併。以下以可信入口提供、依呼叫順序不倒退的接收時間計數，視窗為 `(now_ms - 600000, now_ms]`。這不是依原始事件時間處理遲到資料的範例。

```lua
-- KEYS[1]: risk:device:<device_id>:fails
-- ARGV[1]: 可信入口的接收時間（Unix 毫秒）
-- ARGV[2]: 事件 ID；同一事件重試必須沿用
local now_ms = tonumber(ARGV[1])
local window_ms = 600000
redis.call('ZREMRANGEBYSCORE', KEYS[1], '-inf', now_ms - window_ms)
redis.call('ZADD', KEYS[1], 'NX', now_ms, ARGV[2])
local count = redis.call('ZCARD', KEYS[1])
redis.call('PEXPIRE', KEYS[1], window_ms)
return count
```

Lua 將清理、寫入、計數與 TTL 設定放在同一次原子執行中。`NX` 讓同一事件在視窗內重試時不改寫時間。去重只涵蓋目前保留的事件；若要防止跨視窗重送，需另存較長期限的事件處理紀錄。測試至少涵蓋同毫秒不同 ID、相同 ID 重送與剛好落在下界的事件。

## 3. 雙核決策引擎：規則引擎 vs. 機器學習模型

### 3.1 動態規則引擎（Rule Engine）

- **優勢**：可記錄命中規則與輸入值供追查；更新速度取決於發布與驗證流程。
- **實作技術**：Drools、Aviator 或自研 AST（抽象語法樹）解譯器。
- **典型規則範例**：
  - _IF `is_proxy_or_vpn == true` AND `transaction_amount > 1000 USD` AND `card_country != ip_country` THEN 觸發 3DS 驗證_。

### 3.2 機器學習模型（ML & GNN 評分）

- **XGBoost / LightGBM**：針對結構化表格特徵輸出 `0.0 ~ 1.0` 的詐欺機率分數。
- **GNN（圖神經網絡）**：黑產集團通常使用同一批手機號碼、代理 IP、WiFi MAC 地址或銀行帳戶註冊成百上千個帳號。
- GCN / GraphSAGE 聚合鄰居特徵來學習節點表示，再由模型產生風險分數。鄰近黑名單節點可以是風險訊號，但分數變化取決於訓練資料、特徵與模型；共享地址或 IP 本身不足以判定詐欺。

## 4. 灰度上線與影子模式（Shadow Mode Evaluation）

風控規則與模型不能直接推上生產環境，任何微小的誤判都可能造成巨額業務損失。

影子模式（Shadow Pipeline）讓新模型只評分、不影響交易：

<RiskShadowPipelineDiagram />

影子測試的觀察期依標籤回收速度與樣本量決定。將決策與可靠標籤比對，檢查 precision、recall、誤攔率與延遲，達標後才逐步放量；僅比較兩版決策差異，無法算出真實準確率。

## 5. 總結

- **極限延遲約束**：同步鏈路依既定延遲預算驗收，例如前述 50ms 目標，重計算與全量圖遍歷必須剝離至非同步串流處理中。
- **規則與模型互補**：以動態規則引擎實現秒級應急攔截，以機器學習與 GNN 圖譜挖掘深層隱蔽黑產。
- **影子模式是生命線**：永遠以真實流量鏡像驗證風控變更，觀察誤攔率並保留回退機制。
