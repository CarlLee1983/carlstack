一個採購助理讀完供應商報價，把品項與金額填進管理後台。按下儲存後，畫面一直轉圈。現在換另一個模型再做一次，究竟是在重試填表，還是在建立第二張採購單？

這是虛構的工程情境。GPT-6.1 Terra 的發布讓大量畫面操作有了新的成本候選，但模型路由若只依難度與單價切換，會漏掉前一次操作留下的外部狀態。我會依動作能否安全重做來分配工作，再比較通過驗收的成本。

## 新模型的強項，適合拿來提出哪一種實驗

OpenAI 於 2026 年 10 月 26 日推出 Terra，[同日系統卡](https://deploymentsafety.openai.com/gpt-6-1-terra/)記載了發布日期。[GPT-6.1 Terra 發布公告](https://openai.com/index/introducing-gpt-6-1-terra/)將模型定位於視覺推理、電腦操作與文字工作，並舉發票讀取和帳務錄入為例。官方也指出，最複雜的程式開發仍適合 GPT-6.1 Sol 或 GPT-6 Astra。這支持按工作類型試用，沒有支持把所有 agent 一次換掉。

資料查核於 2026 年 10 月 27 日。官方效能數字屬供應方評測，這裡沒有重跑 benchmark，也沒有執行採購系統實測。接下來的分工、驗收與停止條件都是工程建議。

採購案例可以先縮成「根據固定報價文件，在測試後台建立尚未送出的草稿」。驗收比對供應商、料號、數量、幣別、稅額與總額，還要確認草稿狀態。不能只因畫面出現綠色提示，就把任務算成功。

## 讀取、填草稿、送出，要有不同的重試資格

讀報價與擷取欄位可以先交給 Terra。輸出附上文件頁碼或原始欄位位置，讓驗收者能查回去。辨識不清的數字保留待確認，避免模型把缺漏補成看似完整的訂單。

下一步是填入草稿。這時已經碰到外部狀態，應先取得可追蹤的草稿 ID，並限制一次任務只操作這張草稿。若頁面逾時，先用 ID 查目前內容，再決定補填缺欄位，不能直接從「新增」重新開始。畫面服務若沒有穩定識別值或可查回的狀態，我會先保留人工處理，而不是把它列為便宜模型的常規工作。

正式送出則另設授權與驗收。它可能產生對供應商的承諾，不能因模型對畫面很有把握，就順便跨過這一步。較大的模型也需要同一條限制，否則升級只換了推理者，沒有消除重複送出的風險。

**送出結果不明時，停止任何再次寫入，先查核外部狀態。** 能查到已送出的單號就接續追蹤；確定未送出才依原授權繼續；無法判定則交由負責人處理。這條規則應在工具層與工作狀態裡實作，不能只留在 prompt。

## 換模型之前，先固定交接證據

假設 Terra 回報料號無法判讀，轉交 Sol 的資料應包括來源文件、已辨識欄位、未確定的位置、草稿 ID，以及最後一次已確認的操作。單純轉送「幫我完成這筆採購」會讓接手者重新猜流程，也可能重做已完成的寫入。

因此，我建議把路由原因分開記錄：辨識不足、欄位驗收失敗、工具錯誤，以及寫入結果不明。前兩類可以在相同資料上比較另一模型；工具錯誤先修整合；寫入不明先查狀態。全部都歸成「模型失敗，換強一點」，會讓升級掩蓋系統問題。

API 整合也有明確條件。截至查核日，[模型文件](https://developers.openai.com/api/docs/models/gpt-6.1-terra)要求工具呼叫使用 Responses API，`reasoning.effort` 預設為 `medium`。若原流程走 Chat Completions 工具呼叫，應先完成 endpoint 適配並確認工具結果能接回，之後固定這套流程比較模型。不要同時更換 API、工具契約與模型，再把所有差異算到 Terra 身上。

## 價格便宜，仍要分開記錄拒收與人工救援

[官方模型頁](https://developers.openai.com/api/docs/models/gpt-6.1-terra)的 Standard 費率為每百萬 token：輸入 US$1、快取輸入 US$0.05、輸出 US$5。快取寫入依保留時間另計，30 分鐘為 US$1.25，12 小時為 US$2.50。輸入超過 272K tokens 時，整個請求的輸入與快取費率乘二，輸出乘 1.5；不是只替超出部分加價。

這些條件會影響要帶多少歷史畫面與文件。連續操作的上下文若不斷成長，後面的步驟可能使用不同費率；實際記帳應核對 API usage 與帳單的可用欄位，分開一般輸入、快取讀寫與計費輸出，並加入工具與執行費。不要把所有輸入都套上快取命中價格。

站內已有[每個驗收任務成本的比較方法](/blog/gpt-6-1-sol-cost-per-accepted-task/)與[拒收後升級重跑的算式](/blog/haiku55-subagent-accepted-task-cost/)。採購實驗沿用這些方法，另外記錄因外部狀態不明而停止的案件。這類案件不能算成完成，也不能在統計時排除它已花掉的費用。

## 第一批只開放能查回的草稿工作

可從一組已去識別、答案已知的報價樣本開始，涵蓋相似料號、不同幣別、稅額拆列與刻意缺漏。固定資料、工具權限、推理設定及驗收器，先在測試後台比較原模型與 Terra。再注入儲存逾時、重複點擊與回覆遺失，檢查它是否先查草稿，而不是再新增一張。

上線門檻要由團隊事先填上可接受的欄位錯誤率、人工覆核時間與成本。越權送出、重複建立或捏造已完成證據則設為停止條件，發生就暫停擴大流量，保留操作紀錄。回退路由只影響後續工作；已存在的草稿與送出狀態仍需逐筆核對。

下一步可以盤點目前 agent 的畫面動作，替每個寫入補上「用什麼 ID 查回結果」。沒有答案的步驟先留在人工流程。當操作能被驗收與安全接續，Terra 的價格才有機會轉成可持續的節省。
