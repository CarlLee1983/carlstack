在任何具備用戶登入系統的 Web 應用中，**密碼儲存** 是整個資料安全鏈條中最脆弱也是最致命的一環。

歷史上，有無數知名企業（如 LinkedIn、Adobe、Yahoo）因密碼儲存機制不當，在資料庫洩漏時導致數億用戶的明文密碼被黑客在數小時內全部還原破解。

許多非資安背景的工程師直覺認為：_「我用了 SHA-256 甚至 SHA-512 加密，難道還不夠安全嗎？」_

答案是：**極度危險！SHA-256 是為高速校驗而設計的，一張現代消費級 GPU（如 RTX 4090）每秒可以計算數十億次 SHA-256 雜湊，暴力破解 8 位純字母密碼只需幾分鐘！**

本文將帶你深入密碼雜湊的演化史，詳細對比 **PBKDF2**、**Bcrypt**、**Scrypt** 與 **Argon2id** 四大現代慢速雜湊演算法。

---

## 1. 為什麼快速雜湊（MD5 / SHA-256）無法保護密碼？

```text
[ 攻擊者持有 GPU 算力叢集 / ASIC 專用硬體 ]
每秒可計算 10,000,000,000 次 SHA-256!
  │
  ├── 1. 預計算字典與彩虹表 (Rainbow Tables) ──> 瞬間逆向查表匹配
  └── 2. 即時暴力破解 (Brute-Force) ─────────> 8 位英數密碼幾分鐘內全部枚舉破譯!
```

### 防禦核心哲學：讓雜湊「故意變慢」且「消耗大量記憶體」！

安全密碼雜湊演算法的核心思想是**可調工作因子（Cost / Work Factor）**：

- 對於正常登入用戶，耗費 200 毫秒計算一次雜湊，人類完全無感知；
- 但對於黑客，如果嘗試一次密碼需要 200 毫秒，枚舉 1 億個密碼需要花費 **231 天**，攻擊成本直接飆升至天文數字！

## 2. 四大現代密碼雜湊演算法全景對決

| 演算法       | 誕生時間 / 標準                             | 計算瓶頸維度 (Hardness)                              | 抗 GPU / ASIC 專用硬體破解能力                      | 建議使用場景                                       |
| :----------- | :------------------------------------------ | :--------------------------------------------------- | :-------------------------------------------------- | :------------------------------------------------- |
| **PBKDF2**   | 2000 (RFC 2898 / NIST)                      | **純 CPU 計算密集型** (多次迭代 HMAC)                | 較弱 (GPU 高度平行加速非常容易)                     | 需嚴格符合 FIPS-140 美國聯邦法規審計的合規系統     |
| **Bcrypt**   | 1999 (Eksblowfish 演算法)                   | **CPU + 少量記憶體 (4KB)**                           | 中等 (已存在 FPGA 專用破解硬體，但仍具備不錯安全性) | 成熟老牌系統、廣泛被各大語言框架預設採用           |
| **Scrypt**   | 2009 (RFC 7914)                             | **CPU + 記憶體硬性 (Memory-Hard)**                   | **極強 (需要大量 RAM 記憶體，大幅限制 GPU 並行度)** | 數位貨幣錢包 (如 Litecoin 挖礦防 ASIC)、高安全場景 |
| **Argon2id** | **2015 (密碼雜湊大賽 PHC 冠軍 / RFC 9106)** | **CPU + 記憶體硬性 + 平行執行緒 + 抗時序側信道攻擊** | **🏆 全行業最高防禦天花板**                         | **🔥 現代所有新系統的首選第一推薦！**              |

---

## 3. 終極王者：Argon2id 演算法架構剖析

Argon2 在 2015 年密碼雜湊競賽（Password Hashing Competition）中力壓群雄奪冠，並分為三個變體：

1. **Argon2d**：數據依賴型記憶體存取，抗 GPU 算力最強，但容易遭受時序側信道攻擊（適合數位貨幣挖礦）；
2. **Argon2i**：數據無關型存取，抗時序側信道攻擊；
3. **Argon2id（黃金混合版）**：在第一遍內存填充時使用 Argon2i 模式抵抗側信道，在後續填充中使用 Argon2d 抵抗 GPU 暴力枚舉，**兼具兩者之長**！

### OWASP 推薦的 Argon2id 標準配置參數

```python
import argon2

# OWASP 推薦安全參數 (兼顧安全與 200ms 以內伺服器延遲)
hasher = argon2.PasswordHasher(
    time_cost=3,        # 迭代輪數 (Iterations)
    memory_cost=65536,  # 記憶體消耗 (64 MB RAM)
    parallelism=4,      # 平行執行緒數 (4 Threads)
    hash_len=32,        # 輸出雜湊長度 (Bytes)
    salt_len=16         # 隨機鹽長度 (16 Bytes CSPRNG 生成)
)

# 1. 密碼加密
hashed_str = hasher.hash("MySuperSecurePassword123!")
# 輸出格式: $argon2id$v=19$m=65536,t=3,p=4$<salt>$<hash>

# 2. 登入驗證
try:
    hasher.verify(hashed_str, "MySuperSecurePassword123!")
    print("驗證通過!")
except argon2.exceptions.VerifyMismatchError:
    print("密碼錯誤!")
```

## 4. 密碼儲存的黃金鐵律清單

1. **加鹽（Salt）是標配且必須由 CSPRNG 生成**：每個用戶的鹽必須全域隨機且唯一，長度至少 16 字節，徹底粉碎彩虹表。
2. **絕不自己發明加密演算法（Don't Roll Your Own Crypto）**。
3. **支持自動重新雜湊（Re-hash on Login）**：當未來伺服器硬體升級、需要將 Argon2 記憶體消耗從 64MB 調高至 128MB 時，在用戶每次成功登入時自動檢測並以新參數重新 Hash 覆寫資料庫。

---

## 5. 總結

- **全新專案**：無條件首選 **Argon2id**（RFC 9106）。
- **既有系統維護**：可繼續穩定使用 **Bcrypt**（Cost 設定在 12 以上）。
- **絕對禁止**：任何場景使用 MD5、SHA-1、SHA-256 儲存用戶密碼。
