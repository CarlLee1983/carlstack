## 視覺化退化：方塊、箭頭與「看似理解」的幻覺

軟體架構圖在過去二十年間陷入了高度同質化的形式主義：圓角矩形代表服務，帶箭頭的虛線代表 RPC 呼叫，圓柱體代表資料庫。當工程師需要向團隊解釋複雜的系統機制——例如 Token Bucket 限流的水位溢出、Raft 的心跳租約、或是快取鍵的命中邏輯時——這些方塊圖往往只能呈現拓撲位置，卻無法建立機制運作的「物理直覺」。

讀者看到方塊與箭頭時，大腦必須在腦海中額外進行一層昂貴的抽象轉換：這個箭頭代表推還是拉？這個圓柱體的容量極限在哪裡？為什麼流量暴增時下游會反壓？

由開發者 Ryan（@wheresryan22）於 2026 年 10 月開源的 Claude Code Skill [wheresryan22/anatomy](https://github.com/wheresryan22/anatomy)，在短短數天內狂攬超過 3,600 顆 GitHub 星星。它的核心設計哲學徹底顛覆了現代軟體圖解的慣例：**物件即解釋（The object is the explanation）**。與其繪製懸空的圖表標籤，不如直接發明一座真實、嚴密、且符合物理工藝的實體機械裝置。

## 物件即解釋：實體隱喻的機制對應

在 Anatomy 的設計規格中，任何模糊或扁平的圖形都被視為未完成的缺陷。一個真正能解釋系統概念的裝置，必須由至少 40 到 80 個具備厚度、接合面與螺絲固定的實體零件組成。當讀者看到真實儀器的齒輪咬合與指針偏轉時，系統內核的運作規律便不言自明。

在具體工程領域中，Anatomy 將常見的抽象演算法精準映射為經典精密儀器：

- **Token Bucket 限流器與突發配額**：被建構為帶有雙導軌的滑動工作台，左側承裝具備刻度尺的精密圓柱容積槽，右側以千分錶探針即時偵測桶槽位移。當令牌消耗過快，探針偏轉抵達硬限位，機械結構物理卡死。
- **快取鍵檢查與跳過重複運算**：被設計為一座彈子鎖（Pin-tumbler lock）。只有當所有的彈子幾何形狀完全對齊剪切線（Shear line）時，鎖芯才能旋轉並觸發快取命中；任何一個參數未命中，實體結構直接阻擋執行。
- **共用 GPU Context 與多 Canvas 渲染**：被具象化為龍門式繪圖儀（Gantry plotter）。單一列印噴頭沿著高精度滑軌依次巡邏 16 個獨立儲存井，直觀解釋單一管線在不同渲染目標間的時序切換。
- **二維分離高斯卷積（49×49 次取樣降至 49+49）**：以一張釘床印章對比兩把安裝在正交軌道上的精細梳齒，將演算法的空間維度降階轉化為清晰的幾何干涉。

## 零幻覺驗收：幾何審計與工藝約束

許多宣稱具備繪圖能力的 AI 工具，產出的往往是透視失真、管線懸空或線條穿模的「AI 幻覺圖」。Anatomy 之所以能在生產級工程團隊中落地，關鍵在於它建立了一套不依賴肉眼調校的數學審計迴圈（Audit Loop）。

在 Anatomy 的建構管線中，SVG 不只是一串向量座標，而是三維世界空間坐標（x, y 沿底板平面，z 朝上）經過 42° 方位角與 30° 仰角等角投影後的投影結果。所有管線、零件與軸承都必須通過內建審計腳本的嚴格檢驗：

```bash
# 執行幾何拓撲審計：穿模、懸空、折角、支撐與畫家深度排序
node build.mjs --audit
# 驗證線條閉合度：所有刻度、接縫與指針必須終結於外框或螺絲節點
node scripts/lines.mjs page.html --out shots/lines.png
```

這套幾何審計強制執行以下停機規則：

1. **嚴禁管線懸空穿模**：任何管線不得穿越實體零件或另一條管路，在爆炸圖與靜止狀態下均必須維持至少 1.5 倍管徑的物理間隙；管線終端必須落地於法蘭盤、接頭或接地端子。
2. **真深度排序（True Depth Sorting）**：當兩條路徑在螢幕上交叉時，前後順序必須由光線投射與深度判定計算，禁止手動硬編碼圖層順序。
3. **紋理終結定理**：螺栓圈、卡尺刻度、散熱槽與倒角接縫，絕對不能在表面中途憑空中斷，必須完整閉合或包裹至側面。

## 工程落地：從終端 Prompt 到發布標準

Anatomy 本質上是一套專為 Coding Agent（如 Claude Code、Codex）打造的 Agent Skill。工程師只需在工作區安裝擴充：

```bash
npx skills add wheresryan22/anatomy
```

在日常架構規劃或編寫技術文檔時，可以直接在提示詞中下達指令：

> "以等角精密機械測台的形式，繪製 Redis 單執行緒事件循環與非同步 AOF 寫盤的運作機制，需要具備工作台底座、傳動凸輪、刻度指針與油壓緩衝閥。"

Agent 會自動啟動尺寸估算（Figure 40–80 零件 / Hero 80–150 零件）、建立純數學模型、排定零件深度，並編譯出符合 WCAG 對比度規範與站台主題 Token 的原生 SVG 代碼。

## 下一步：在你的架構文檔中引入「實體直覺」

系統架構說明的終極目標不是展示複雜度，而是降低讀者的認知負載。在下一次編寫核心演算法或分散式交易機制的技術文件時，嘗試放棄習慣的方塊圖架構：

1. 列出該機制的核心物理量：容量、閥值、流速、鎖狀態。
2. 尋找與該物理量一對一映射的經典儀器（如天平、離心調速器、凸輪軸、水準儀）。
3. 透過 Anatomy 建立零件幾何與深度排序，輸出可嵌入文檔的原生向量圖。

當系統的運作方式被固化為一座精密運轉的實體機器，架構決策的邊界與瓶頸，在第一眼凝視時就已經得出答案。
