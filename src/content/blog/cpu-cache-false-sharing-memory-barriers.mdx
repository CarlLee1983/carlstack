現代多核心處理器（Multi-core CPU）的運算時脈多在 3GHz ~ 5GHz，每秒可執行數十億條指令。

**主記憶體（DRAM）的存取延遲卻有 50ns ~ 100ns（相當於數百個 CPU 時脈週期）。** 如果 CPU 每次讀寫變數都要直接存取主記憶體，運算核心會有 99% 的時間在空等資料。

這就是「記憶體牆（Memory Wall）」問題。晶片架構師的解法是多層級的高速 SRAM 快取（L1、L2、L3 Cache）。

但快取一多，分散式系統的老問題也搬進了晶片：**快取一致性（Cache Coherence）** 與 **偽共享（False Sharing）**。

以下拆解 MESI 協定，以及無鎖高效能程式設計裡的快取行對齊技巧。

### CPU 以快取行（Cache Line）為最小傳輸單位

CPU 快取讀取記憶體時，一次固定讀一整個連續區塊，也就是**快取行（Cache Line，現代 x86/ARM 架構標準均為 64 Bytes）**。就算只需要一個 4 位元組或 8 位元組的變數，也是整行讀進來。

## 2. 快取一致性協定：MESI 狀態機

多個 CPU 核心同時載入包含同一個變數的 Cache Line 時，硬體用 **MESI 協定** 保證資料一致性：

| 狀態  | 全稱              | 意義說明                                                                         |
| :---- | :---------------- | :------------------------------------------------------------------------------- |
| **M** | Modified (已修改) | 該 Cache Line 只存在於目前核心的快取，且已被修改（與主記憶體不一致），是髒資料。 |
| **E** | Exclusive (獨占)  | 該 Cache Line 只存在於目前核心的快取，資料乾淨（與主記憶體一致）。               |
| **S** | Shared (共享)     | 該 Cache Line 同時存在於多個核心的快取，資料乾淨。                               |
| **I** | Invalid (無效)    | 該 Cache Line 的資料已失效，讀取時必須重新從匯流排或主記憶體載入。               |

## 3. 偽共享（False Sharing）：隱形的效能殺手

兩個完全無關的變數，如果剛好被分配在**同一個 64 位元組的 Cache Line 中**，就會發生偽共享：

1. Core 0 上的執行緒 0 頻繁修改 `a`。
2. 依照 MESI 協定，Core 0 必須向匯流排發送 Invalidate 訊息，把 Core 1 的整個 Cache Line 標記為無效。
3. Core 1 上的執行緒 1 要修改 `b` 時，發現自己的 Cache Line 已失效（I 狀態），只能暫停運算，從 L3 或主記憶體重新載入。
4. Core 1 修改 `b` 後，又反過來把 Core 0 的 Cache Line 標記為無效。

**結果**：兩個執行緒在邏輯上沒有任何競爭，卻在晶片匯流排上引發「快取行乒乓效應（Cache Line Bouncing）」。多執行緒沒有帶來加速，效能反而暴跌 10 倍以上。

## 4. 偽共享的實戰工程解法：快取行對齊與填充（Padding）

### 4.1 C/C++ struct 記憶體對齊

用編譯器指令強制變數獨占 64 位元組：

```c
struct alignas(64) WorkerThreadState {
    uint64_t counter; // 8 bytes
    // 編譯器自動填充 56 bytes padding，確保每個實例跨越不同的 Cache Line
};
```

### 4.2 Java 中的 `@Contended` 與 LMAX Disruptor 環形佇列

低延遲撮合架構 **LMAX Disruptor** 的序號變數，用位元組填充消除了偽共享：

```java
// 手動填充 7 個 long (56 bytes) 加上本體 8 bytes = 64 bytes
public class Sequence {
    public long p1, p2, p3, p4, p5, p6, p7; // Cache line 前置填充
    public volatile long value = 0L;         // 核心計數變數
    public long a1, a2, a3, a4, a5, a6, a7; // Cache line 後置填充
}
```

## 5. 記憶體屏障（Memory Barriers / Fences）

現代 CPU 為了榨出管線效能，有 **亂序執行（Out-of-Order Execution）** 與 **寫入緩衝區（Store Buffers）**：

- 單執行緒下保證 As-if-serial 語意（最終結果正確）。
- 多執行緒下，Core 0 的寫入可能很久之後才刷新到快取，Core 1 看到的執行順序可能完全顛倒。

高併發無鎖演算法（如 CAS、Lock-Free RingBuffer）必須精確使用 **Acquire-Release 語意**，用最低的硬體開銷確保跨核心的可見性與有序性。

## 6. 總結

1. **空間局部性與時間局部性**：善用 CPU 順序讀取與 Cache Line 預取（Prefetching）。
2. **留意偽共享**：高併發的熱點計數器、無鎖佇列與多執行緒累加器，用 64 位元組對齊隔離併發寫入。
